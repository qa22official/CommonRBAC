# Design

## Context

仓库已完成多模块 Maven 骨架与 `rbac-api` 契约层（3 个注解、`PermissionResolver`、`AuditRecorder` 与两类事件、`CurrentUser` / `IdentitySnapshot` / `IdentityQuery`），其余 6 个模块只有 `package-info.java`。参考实现已全部就绪。本仓库不使用 Spring Security 框架，鉴权自行实现。

项目 `config.yaml` 与 `docs/` 目录下（00 基线 → 01 需求 → 02~06 设计）是本次实现的单一事实来源。6 个 capability spec（见 `specs/auth` 等）定义 WHAT；本文件定义 HOW——关键决策与权衡。

关键约束：Java 21、Spring Boot 3.x、MyBatis、MySQL 8、Redis Pub/Sub（不做分布式锁）；模块化单体、无状态、3 实例起步；MySQL/Redis/Nginx 均为单实例无自动故障切换；RBAC 写 QPS < 1；不做数据权限、不做多租户、不做 SSO/OAuth、不做 DSD。

## Goals / Non-Goals

**Goals**

- 构建 RBAC0 后端：认证（JWT + BCrypt + 限流/锁定）、鉴权（过滤器 + 拦截器 + PermissionResolver + 默认拒绝）、缓存（三份映射 + Redis Pub/Sub + TTL + fail-open）、管理端 CRUD（含覆盖式授权并发保护）、审计（CHANGE 同事务 / SECURITY 独立）。
- 满足 00 基线的完成定义（每个受保护接口有且只有一个鉴权声明、默认拒绝测试通过、令牌作废 30 秒内收敛、并发授权不静默丢失、CHANGE 与业务同事务、SECURITY 有失败计数与告警、所有业务接口显式审计意图、权限变更跨实例 1 秒生效、指标齐全）。
- 让 2,500 QPS 稳态、4,000 QPS 冲刺满足 06 性能文档口径；鉴权类接口 P99 ≤ 30ms。
- 为 RBAC1 角色继承与 RBAC2 约束校验链预留扩展位，但本期只做零值占位与不改动业务代码的兼容验证。

**Non-Goals**

- RBAC1/2/3 的角色继承（`inherit_role_id` 字段设为 0）与 RBAC2 静态/动态约束（`ConstraintValidator` 链只实现 4 条内置保护校验器）。
- 数据权限、行级/字段级权限、SSO/OAuth2、第三方认证、工作流审批、DSD、微服务网关/注册中心、分布式锁、专用日志数据库。
- 前端 v-perm 指令、菜单/路由动态渲染（由单独变更覆盖）。
- 跨机房部署（假设应用、MySQL、Redis 同机房，内网延迟 < 0.5ms）。

## Decisions

### D-1 鉴权零持久访问：本地三份缓存 + 单飞惰性重载

**决策**：实例本地缓存只存事实（roleId→codes、userId→roleIds、userId→{tokenVersion,status}），不存派生结果（userId→权限码集合）。鉴权主链路只读本地缓存，永不访问 DB 或 Redis。缓存未命中（首次或失效后）时单飞查询数据库，一次合并三种事实。

**替代方案**：缓存派生值 userId→权限码集合。放弃原因：改一个角色会让上万 userId 缓存作废，派生缓存的价值被其失效代价抵消。

**依据**：02 §3 缓存结构、02 §10 鉴权链路、02 §11 失效与降级、00 §3.5 缓存失败策略。

### D-2 三层失效机制：主动广播 → TTL 兜底 → 实例生命周期

**决策**：写操作事务提交成功后（顺序不可颠倒）自增版本号并发布 Redis Pub/Sub 消息（`PERM_CHANGED` / `TOKEN_REVOKED` / `TOKEN_REVOKED_GLOBAL`），订阅方只标记失效不立即重载。TTL 统一 30 秒，调整必须同步修改 01 FR-A9。订阅重连成功强制清空全部缓存。

**替代方案**：立即重载。放弃原因：N 个实例同时查库形成写尖峰。采用被动惰性重载。

**依据**：02 §11.1、01 §4.1.1 FR-A9 时效承诺。

### D-3 缓存失败姿态 fail-open + 强制 fail-closed 分支

**决策**：`rbac.cache.stale-policy=fail-open` 默认，重载失败继续用最后一份成功数据。两个强制 fail-closed 分支：① 收到 `TOKEN_REVOKED(X)` 但 X 的快照重载失败 → 拒绝 X（40101）；② 数据库不可用且实例从未成功加载任何缓存 → 503。

**替代方案**：fail-closed（直接拒绝）。放弃原因：会把 Redis 或 DB 的短时抖动放大成大规模登录阻断，与"鉴权 99.9%"目标冲突。

**依据**：02 §11.3、01 AC-10、00 §3.5。

### D-4 并发授权保护：FOR UPDATE + 版本号乐观锁

**决策**：覆盖式授权接口必须携带 `expectedVersion`。事务内先 `SELECT ... FOR UPDATE` 锁角色行 → 校验约束 → 覆盖写入关系表 + 写 CHANGE 审计 → 提交。版本不匹配返回 40950。

**替代方案**：只用乐观锁不加行锁。放弃原因：两个请求恰好同时读到相同版本号，乐观锁的"版本自增"仍会在一个提交成功后另一个被拒绝，但约束校验（如"不得移除 SUPER_ADMIN 的 `*`"）本身不具备原子性；行锁负责防止约束被并发绕过。

**依据**：00 §3.8、04 §1.7、03 §6.1。

### D-5 JWT 密钥三阶段轮换协议

**决策**：阶段 1 配置变为双密钥 → 阶段 2 签发方切换 + 双密钥验签 ≥ 访问令牌最长有效期 → 阶段 3 确认无旧 kid 验签记录后移除旧密钥。密钥泄露时跳过等待期并自增 `token_version` 基线。

**替代方案**：直接切换单密钥。放弃原因：切换瞬间所有旧令牌立即失效，等于强制全员重新登录，不具备可回滚性。

**依据**：02 §9 密钥轮换。

### D-6 审计两类事务语义

**决策**：CHANGE 与业务同事务，审计失败 = 业务回滚；SECURITY 独立落库，失败不回滚业务但必须计数与告警。导出类固定结构写入 `detail_after`。业务域快照脱敏由各业务模块自行负责。

**替代方案**：统一异步审计。放弃原因：CHANGE 审计与业务的因果关系被切断，"业务成功但 CHANGE 审计缺失"变成常态。

**依据**：01 §4.5、00 §3.7。

### D-7 Flyway 单一序列 + 多人分段版本号 + 不使用物理外键

**决策**：单库单序列，脚本 V200 起按模块前缀分配（如 V201_user、V210_role_permission、V220_audit、V230_init_data）。引用校验在事务内用 `SELECT ... FOR UPDATE` + JVM 锁实现。

**替代方案**：物理外键。放弃原因：Flyway 在空库上首次执行时外键建立顺序复杂；且物理外键使逻辑删除与软引用的语义变得模糊。

**依据**：00 §4。

### D-8 `PermissionResolver` 单一实现，契约不可变

**决策**：`PermissionResolver.resolve(long userId)` 签名固定；返回不可变集合；不返回 null；不抛出与权限无关的异常。RBAC1/2 升级只改这个实现内部（沿 `inherit_role_id` 收集并集、按 `ConstraintValidator` 链校验），业务代码与鉴权主链路不变。

**依据**：D-1（零持久访问约束要求权限集合的计算集中在一处）、00 §3.1、05 §7 升级代价。

### D-9 ArchUnit 七项依赖规则 + 四种构建门禁

**决策**：依赖边界由 ArchUnit 强制；权限注解覆盖、权限码一致性、审计声明、敏感关键词四项为自定义构建期门禁。

**替代方案**：纯人工 Code Review。放弃原因：规则多、易漏，且"漏加注解"本身就是安全漏洞的主要来源。

**依据**：02 §19、00 §5 质量门禁。

## Risks / Trade-offs

| 风险 / 权衡 | 设计姿态 | 缓解 / 代价 |
|---|---|---|
| fail-open 期间放行陈旧权限 | 接受 | 必须暴露陈旧时长、放行请求数、受影响用户数三类指标；故障恢复后立即全量重载 |
| 30 秒 TTL 内令牌作废延迟 | 接受（FR-A9 明确承诺） | Redis 可用时 ≤ 1 秒；Redis 不可用时 ≤ 30 秒；文档明确写"不得承诺任何故障下都立即失效" |
| 三份本地缓存占用内存 | 接受 | 预算 10k 用户 × 平均 3 角色 × 平均 30 权限码 ≈ 20MB，远低于容器上限 |
| BCrypt 故意慢（50~150ms） | 接受 | 登录接口独立线程池隔离；不计入 30ms 鉴权 P99 |
| MySQL/Redis/Nginx 单点无自动切换 | 接受 | RTO/RPO 按 01 需求文档承诺；必须做异机备份与季度恢复演练 |
| RBAC0 权限码集不展开通配（如 `sys:*` 不展开为 `sys:user:*`） | 本期只做"集合 contains 或 contains 通配前缀匹配"，不做预展开 | 主链路保持 O(1)；通配计算仅在 `PermissionResolver` 内，不影响拦截器判定 |
| 业务域快照脱敏由业务模块负责 | 接受 | 不在鉴权域统一脱敏器（RBAC 脱敏器无法预知业务字段敏感规则）；通过接口自查清单管理风险 |
| Docker 镜像层不得含密钥 | 接受 | 密钥由环境变量下发，启动时校验 kid→密钥映射一致，不一致启动失败 |

## Migration Plan

本次是新建工程，无存量数据，"迁移"指首次部署：

1. 准备阶段：目标环境部署 MySQL 8、Redis、Nginx（单实例）；配置环境变量（JWT 密钥 ≥ 256 位，至少一个 kid）；写入 `application.yml` 覆盖项。
2. 首次启动：启动应用；Flyway 自动创建 RBAC 表、审计表、内置角色/权限码、admin 默认账号。
3. 健康检查：`/actuator/health` 返回 UP；admin 账号登录成功；默认密码必须首次登录后修改。
4. 故障演练（上线前）：手动停 Redis 观察鉴权不中断；手动停 MySQL 观察 fail-open 行为与指标；手动重启应用观察缓存空、首个请求读库。
5. 发布顺序强制（密钥轮换）：先让全部实例支持双密钥 → 切换签发 → 等待 ≥ 访问令牌最长有效期 → 确认无旧 kid 验签记录 → 移除旧密钥。回滚：阶段 1、2 任意时刻切回双密钥 + 旧签发。

回滚策略：由于是新建项目，回滚即"停止应用 + 删除数据卷"。密钥泄露场景的紧急回滚：全局自增 `token_version` 基线（`TOKEN_REVOKED_GLOBAL`）+ 签发密钥临时改为新密钥。

## Open Questions

下列未知不改变 spec、设计、任务拆解，可在 apply 阶段处理：

- **O-1 通配权限码的主链路匹配口径**：设计层已倾向"集合 contains 或 contains 通配前缀匹配"而非"预展开"。apply 阶段按性能实测决定；当前任务拆解不依赖这个细节。
- **O-2 admin 默认密码的初始值**：apply 时选定并提交到安全配置；不写进设计文档。
- **O-3 前端接入**：后端 API 完成后，前端的登录页、权限管理页由单独变更覆盖；本变更不含前端实现。
