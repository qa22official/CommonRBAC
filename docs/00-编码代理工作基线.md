## 2. 当前实现范围

### 2.1 本期必须实现

- RBAC0：用户、角色、权限、用户角色关系、角色权限关系；
- 账号密码登录、登出、续期、修改密码；
- 用户、角色、权限和授权关系管理；
- API、菜单、按钮三类功能权限；
- `@PublicApi`、`@RequiresLogin`、`@RequiresPermission`；
- 默认拒绝；
- 变更审计和安全事件审计；
- 本地权限缓存、Redis 失效通知、TTL 兜底；
- 身份快照缓存和 `token_version` 校验；
- 登录限流和失败锁定；
- Flyway、ArchUnit、权限覆盖检查和越权测试。

### 2.2 本期禁止实现

- 多租户；
- 数据权限、行级权限、字段权限；
- SSO、OAuth2、第三方认证；
- 工作流审批；
- DSD 动态角色激活；
- 用 URL 运行时匹配权限；
- 把角色名称或角色编码写入业务代码或前端权限判断；
- 为本期需求引入微服务、网关、注册中心、WebFlux、分布式锁或专用日志数据库。

## 3. 硬性架构约束

### 3.1 模块和依赖

- 使用 Java 21、Spring Boot 3.x、MyBatis、MySQL 8、Redis、Vue 3、TypeScript。
- 架构为模块化单体；模块之间通过 `rbac-api` 的接口、DTO、事件和注解通信。
- `rbac-bootstrap` 是唯一允许依赖全部模块的装配模块。
- `rbac-guard` 不直接访问数据库。
- `PermissionResolver` 的对外契约固定为“输入 `userId`，输出只读权限集合”。
- `ConstraintValidator` 只校验授权意图，不直接写数据库。

### 3.2 鉴权

请求处理顺序固定为：

```text
JWT 验签
→ 用户身份快照与 tokenVersion/status 校验
→ 注解判定
→ PermissionResolver
→ 权限码匹配
→ 进入业务方法
```

- 未标注三种鉴权注解之一的接口默认拒绝。
- `@RequiresPermission` 只接受 API 权限码或通配权限码。
- 前端权限只用于菜单、路由和按钮展示，不能作为安全边界。
- 业务代码不得判断角色名、角色编码或超级管理员身份。
- JWT 不包含权限明细。
- JWT 至少包含：`userId`、`tokenVersion`、`kid`、`iss`、`aud`、`iat`、`exp`。
- 使用 HS256；所有实例必须同时支持当前密钥和轮换中的旧密钥。

### 3.3 令牌失效承诺

不承诺“任何时候绝对立即失效”，采用以下口径：

| 场景 | 要求 |
|---|---|
| 正常 Redis 可用 | 1 秒内传播 |
| Redis 故障 | 最长 30 秒内收敛 |
| 应用实例重启 | 首次访问身份快照为空，必须读库校验 |
| 数据库故障 | 受影响用户拒绝，不得使用未知身份状态放行 |

Redis Pub/Sub 只负责加速通知，数据库中的 `token_version` 和用户状态才是事实来源。

### 3.4 缓存失败策略

- 权限缓存只缓存事实或可验证快照，不缓存不可失效的隐式结果。
- 缓存元数据必须包含 `loadedAt`、来源版本和状态。
- 重载失败不得刷新 `loadedAt`，不得无限延长旧数据有效期。
- 当前产品选择 `fail-open`：保留最后一份成功数据并告警。
- 已知发生状态变化的用户必须拒绝，不能使用旧身份快照。
- 数据库恢复后必须立即全量重载。
- 必须暴露陈旧时长、重载失败、受影响请求和恢复重载指标。
- 设计保留 `stale-policy` 开关，未来可切换 `fail-closed`。

### 3.5 RBAC1 字段语义

角色表使用：

```text
inherit_role_id = 当前角色从哪个角色继承权限
```

它不是组织上级字段。权限计算沿继承来源链向上收集并集。禁止恢复使用含义不明确的 `parent_id`。

RBAC0 阶段所有 `inherit_role_id = 0`，升级后无继承用户的权限快照必须与升级前一致。

### 3.6 审计

审计分为两类：

| 类型 | 事务 | 失败策略 |
|---|---|---|
| `CHANGE` | 与业务变更同事务 | 审计失败则业务回滚 |
| `SECURITY` | 独立写入 | 不回滚业务；允许丢弃但必须计数、告警 |

密码、密码哈希、令牌、密钥不得进入日志、审计快照、响应或异常信息。

### 3.7 授权并发

- 覆盖式授权接口必须携带 `expectedVersion`。
- 版本不匹配返回 `40950`，不得静默覆盖。
- 事务内必须锁定目标用户或目标角色行，再执行约束检查和覆盖写入。
- 乐观锁负责发现丢失更新；行锁负责防止约束并发绕过。

### 3.8 可用性边界

- 应用部署 3 实例。
- MySQL、Redis、Nginx 当前均为单实例，不提供自动故障切换。
- 必须做异机备份和季度恢复演练。
- 不得在代码或文档中宣称整体具备 99.9% 自动容灾能力。
- RTO、RPO 和故障行为以 README 的 ADR-18 为准。

## 4. 数据库实现规则

- 使用 Flyway；已发布迁移脚本禁止修改。
- 不使用物理外键；所有引用校验必须在事务内完成。
- 用户、角色、权限使用逻辑删除。
- 关系表必须有防重复的主键或唯一约束。
- 所有 SQL 使用 MyBatis `#{}` 参数绑定，禁止 `${}` 拼接。
- 任何新增索引都必须提供查询场景、选择性、写入代价和 `EXPLAIN ANALYZE` 结果。
- 模糊查询只实现前缀匹配；禁止默认实现 `LIKE '%keyword%'`。
- 审计查询必须带时间范围和游标条件。
- 授权版本字段：`sys_user.role_version`、`sys_role.perm_version`。
- 审计字段至少包含：`audit_category`、`transaction_id`、`event_time`。

## 5. HTTP 实现规则

- 基础路径 `/api`，JSON，字段使用驼峰。
- 成功响应 `code=0`；错误使用既定 HTTP 状态和业务码。
- 认证失败返回 401；权限不足返回 403；并发版本冲突返回 40950。
- 创建依赖数据库唯一约束；集合覆盖和目标状态操作必须幂等。
- 不在错误响应中返回所需权限码、堆栈、SQL、密钥或敏感字段。
- `ClientIpResolver` 是唯一客户端 IP 解析组件；限流、审计、告警必须复用它。
- 只有来自可信代理网段的 `X-Forwarded-For` 才可被信任；应用端口不得直接对公网开放。

## 6. 推荐编码顺序

1. 创建 Maven 多模块工程和依赖；
2. 创建 Flyway RBAC0 表、索引和初始化数据；
3. 实现 `rbac-api` 的 DTO、事件、注解和接口；
4. 实现领域模型、权限计算和约束校验；
5. 实现身份快照、权限缓存、失效通知和重载状态；
6. 实现 JWT、密码、登录限流和会话接口；
7. 实现鉴权过滤器、拦截器和统一异常；
8. 实现管理端接口和 CHANGE/SECURITY 审计；
9. 实现前端权限状态、菜单、路由和按钮指令；
10. 增加构建门禁、单元测试、集成测试、并发测试；
11. 用目标数据量执行索引验证和压测；
12. 完成 Redis、数据库故障、实例重启、密钥轮换演练。

每完成一个阶段，必须运行该阶段最小测试集；不要等全部功能完成后再首次验证。

## 7. 编码代理输出要求

每次改动必须说明：

1. 修改的文件和原因；
2. 受影响的接口、表、缓存或权限码；
3. 使用的设计条款；
4. 新增或修改的测试；
5. 未解决的冲突或假设。

如果需要修改本基线或 README 中的 ADR，必须先说明原因，并同步更新受影响专题文档。

## 8. 完成定义

- 所有受保护接口有且只有一个鉴权声明；
- 默认拒绝和越权测试通过；
- 令牌失效、缓存失效、Redis 丢消息、实例重启测试通过；
- 授权并发冲突返回 40950，不能静默丢失更新；
- CHANGE 审计与业务事务一致；
- SECURITY 事件具备失败计数和告警；
- 角色继承方向测试通过，RBAC0 快照无变化；
- 目标数据量下关键 SQL 的执行计划已验证；
- 2,500 QPS 稳态和 4,000 QPS 冲刺满足 [06-性能与容量设计.md](./06-性能与容量设计.md) 的验收口径；
- 文档、迁移脚本、接口清单、权限码清单和测试结果一致。
