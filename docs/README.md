## 决策记录

| 编号 | 决策 | 结论 |
|---|---|---|
| ADR-01 | 架构形态 | 模块化单体；一套 Spring Boot 应用，内部按模块隔离，多实例无状态部署 |
| ADR-02 | 组织模型 | 单组织；所有表不带 `tenant_id` |
| ADR-03 | 鉴权数据存放 | 实例本地缓存 + Redis 广播失效 + 30 秒 TTL；身份快照单独一份（见 ADR-13） |
| ADR-04 | 权限抽象 | 统一用权限码表达；分 MENU / BUTTON / API / SYSTEM 四类；业务代码不引用角色概念 |
| ADR-05 | 权限范围 | 只做功能权限，不做数据权限（行级、字段级） |
| ADR-06 | 安全框架 | 不引入 Spring Security 框架；自研 JWT 过滤器 + 鉴权注解；密码哈希仅用 `spring-security-crypto` 单包 |
| ADR-07 | 并发模型 | 同步阻塞（内嵌 Tomcat）；不使用 WebFlux；不使用虚拟线程 |
| ADR-08 | 数据访问 | MyBatis 手写 SQL；不使用 JPA |
| ADR-09 | 审计 | 分 CHANGE（与业务同事务，不丢弃）与 SECURITY（独立落库，可丢弃但计数告警）两类 |
| ADR-10 | 升级路径 | RBAC0 起步；预留 `inherit_role_id` 字段与两个代码扩展点 |
| ADR-11 | 迁移管理 | Flyway 管理 DDL 版本 |
| ADR-12 | 性能口径 | 推导峰值 2,500 QPS；设计目标 2,000 QPS；验收 2,500 稳态 + 4,000 冲刺；鉴权类接口 P99 ≤ 30ms |
| ADR-13 | 令牌作废时效 | 正常 ≤ 1 秒；Redis 故障 ≤ 30 秒；实例重启立即；数据库故障时受影响用户被拒 |
| ADR-14 | 缓存重载失败策略 | fail-open：继续用最后一份成功数据 + 强告警；已知状态变化用户仍拒绝；预留 `stale-policy` 开关 |
| ADR-15 | 覆盖式授权并发保护 | 乐观锁 `expectedVersion`（冲突返回 40950）+ 行级锁，两者同时使用 |
| ADR-16 | 客户端 IP | 由 `ClientIpResolver` 在可信代理边界内解析；限流、审计、告警复用同一结果 |
| ADR-17 | 角色继承字段语义 | `sys_role.inherit_role_id` 表示"从哪个角色继承权限"；不使用 `parent_id` |
| ADR-18 | 高可用边界 | MySQL / Redis / Nginx 全部单实例，无自动故障切换；保留扩展点约束 |
| ADR-19 | 权限码常量归属 | 分层：框架级（`*`、`sys:*`）放 `rbac-api`；业务级（`biz:*`）放各业务模块自己的常量类 |
| ADR-20 | 业务模块耦合面 | 业务模块只允许依赖 `rbac-api`；耦合点仅 `@RequiresPermission` 与 `AuditRecorder` |
| ADR-21 | 审计范围 | RBAC 域全量 + 业务域白名单（按影响面 × 可逆性判定）；业务接口须显式声明审计意图 |

## 设计修订历史

第 1 轮评审共提出 16 个问题，已全部处理并落入各专题文档。要点：

| 问题 | 结论 |
|---|---|
| 令牌作废依赖内存集合，重启或丢消息后旧令牌仍可用 | 改为身份快照 + 版本比对，正确性来自数据库 |
| 缓存重载失败无限期使用旧权限 | 数据保留但 `loadedAt` 绝不伪刷新；陈旧时长必须可观测；恢复后立即重载 |
| 变更审计与安全事件共用事务语义 | 拆成 CHANGE / SECURITY 两类 |
| 覆盖式授权静默丢失更新 | 乐观锁 40950 + 行锁双防线 |
| 模糊查询与多条件查询缺索引验证 | 降级为前缀查询；建立 `EXPLAIN ANALYZE` 验证并回填流程 |
| 无条件信任 `X-Forwarded-For` | 定义可信代理规则，唯一解析组件 |
| 密钥轮换只有原则没有协议 | 补 `kid` 与三阶段轮换协议 |
| "升级改动 0 行"表述过强 | 改为"权限声明与鉴权入口契约不变" |
| 2,500 推导与 2,000 目标关系不明 | 明确推导峰值 / 设计目标 / 验收场景三者关系 |
| 性能数字被当作实现保证 | 明确预算 / 目标 / 实测的口径纪律 |
| `parent_id` 继承方向三处不一致 | 统一为继承来源语义并改名 |
| 高可用边界不清，隐含已具备容灾 | 如实声明全部单点与 RTO/RPO |
| 规则 R-1 与依赖图矛盾，新模块无法接入 | 修正为"模块间只允许依赖 rbac-api"，新增 R-7 |
| 权限码常量归属未定义 | 分层归属 |
| 新增模块 / 接口的约定缺失 | 02 文档新增 10 条约定，并标注门禁盲区 |
| 业务审计无判据、容易漏审 | 给出影响面 × 可逆性判据；强制显式声明；关键词门禁兜底 |

## 术语

| 术语 | 含义 |
|---|---|
| 认证 | 判断"你是谁" |
| 鉴权 | 判断"你能不能做这件事" |
| RBAC0 | 用户 → 角色 → 权限三层模型 |
| RBAC1 | RBAC0 + 角色继承 |
| RBAC2 | RBAC0 + 约束（互斥、基数） |
| RBAC3 | RBAC1 + RBAC2 |
| 权限码 | 标识某个操作的字符串，如 `sys:user:create` |
| 身份快照 | 每实例内存中的 `userId → {tokenVersion, status}`，用于令牌作废判定 |
| 陈旧时长 | 缓存中最后一份成功数据距今的时间；fail-open 下是判断"权限判断有多旧"的唯一指标 |
| fail-open / fail-closed | 数据不可用时"继续放行"与"直接拒绝"两种姿态 |
| P99 | 100 个请求中 99 个的耗时不超过该值 |
| QPS / 在线用户数 | 每秒请求数 / 同时挂着的用户数（两者不是一回事） |
| RTO / RPO | 故障后恢复服务的最长时间 / 最多允许丢失的数据量 |
