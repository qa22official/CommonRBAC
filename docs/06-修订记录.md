## 2026-10-26 · RBAC0 实现与契约补齐

| 编号 | 修改 | 原因 | 影响文档 |
|---|---|---|---|
| R-01 | **RBAC1 继承在阶段 0 实现**（05 §4.3 选择“方案甲”）：权限快照包含 `roleMeta{enabled, inheritRoleId}`，解析时沿 `inherit_role_id` 展开并做 5 边深度与环保护；RBAC0 数据下为恒等变换 | 00 §8 完成定义已要求“角色继承方向与深度保护测试通过”，Q-9 需拍板；预埋可避免升级时同时改算法与数据 | 05 §4.3、README Q-9 |
| R-02 | `rbac-api` 契约扩展：`CurrentUser.username`、`AuthAccount.failCount`、`TokenVerifier`/`VerifiedToken`、`PermissionStatusQuery`、`PermissionCodeFormat`、`RequestContext`、`BusinessException`、`UserAuthService.resetLoginFailures` | 认证、鉴权、审计、缓存跨模块协作需要显式契约；避免各模块复制权限码规则或从 Web 层取上下文 | 02 §4.1、02 §9、02 §10 |
| R-03 | 角色 DTO 增加 `inheritRoleId` / `inheritRoleName`；`CreateRoleCommand`、`UpdateRoleCommand` 增加 `inheritRoleId`；`UpdatePermissionCommand` 增加可选 `code` 用于不可变校验 | 实现 05 §4.6 的角色继承字段与 04 §5“权限码创建后不可修改” | 03 §4.2、04 §4、04 §5 |
| R-04 | JWT 载荷增加 `username`（不加入角色、权限明细） | CHANGE 审计需要操作人真实账号；`sub` 是 userId，不能把用户名放进审计而不查库 | 02 §9 JWT 载荷表 |
| R-05 | 新增 `local` / `test` 的 H2（MySQL 模式）数据源与可移植 Flyway DDL；`local` 使用内存库、`test` 使用内存库，生产 `container` profile 仍使用 MySQL 8 | 开发/CI 环境不要求安装 MySQL 与 Redis；同一套 V10/V11 脚本在两种引擎执行，减少验证环境差异。本地 H2 为易失数据，持久化验证走 Compose/MySQL | 03 §9、README |
| R-06 | 新增 `rbac.redis.enabled` 开关与 Noop 失效总线；Redis 启用时才注册 Pub/Sub 监听 | 本地无 Redis 时仍可完整运行；Redis 故障时按 3.5 退化为软 TTL | 02 §11.1、02 §16 |
| R-07 | 审计 JSON 列读取增加 H2 兼容解包（仅去掉一层 JSON 字符串） | H2 将文本写入 `JSON` 列时会包一层字符串；MySQL 仍返回原生文档。避免本地/测试 API 输出与生产不一致 | 03 §4.7 |
| R-08 | 内置角色保护对齐 04 §4：内置角色不允许修改、删除、停用；其 `*` 权限不可移除；角色被继承时同样禁止删除 | 原 05 §3.4 只明确删除/停用；04 的错误表要求“修改/删除内置角色”均拒绝 | 04 §4、05 §3.4 |

| R-11 | 统一异常处理将业务码前缀映射到 HTTP 状态；403 不返回所需权限码；日志/响应不含堆栈与敏感字段 | 落实 04 §1.3、00 §5 | 04 §1.3 |
