# 01 · 需求规格说明书

相关文档：[00 基线](./00-编码代理工作基线.md) · [02 总体设计](./02-总体设计说明书.md) · [03 数据模型](./03-数据模型设计.md) · [04 接口](./04-接口设计.md) · [05 演进](./05-RBAC0到RBAC3演进设计.md) · [06 修订记录](./06-修订记录.md)

## 1. 目标与阶段

把权限判定收敛成一条唯一通道：所有受保护接口通过同一套机制判定，业务代码只声明所需权限码，不关心权限来自哪个角色、角色之间有何关系。

| 阶段 | 目标 | 本文档覆盖 |
|---|---|---|
| 本期 | RBAC0 上线 | 完整设计 |
| 后续 1 | RBAC1 角色继承 | 见 [05](./05-RBAC0到RBAC3演进设计.md) |
| 后续 2 | RBAC2 约束 | 同上 |
| 后续 3 | RBAC3 | 由 1、2 叠加达成 |

核心诉求：升级过程不推翻现有模型、不重写业务代码、不改鉴权主链路。

已确认前提：

| 项 | 结论 |
|---|---|
| 架构形态 | 模块化单体，多实例无状态部署 |
| 组织模型 | 单组织，不引入租户维度 |
| 鉴权数据存放 | 单个 `PermissionSnapshot` + 独立身份快照；Redis 广播失效 + 30 秒软 TTL |
| 权限范围 | 只做功能权限（菜单、按钮、接口），不做数据权限 |
| 审计 | 分 CHANGE 与 SECURITY 两类；范围 = RBAC 域全量 + 业务域白名单 |
| 性能口径 | 10k 并发在线用户；推导峰值 2.5k QPS；设计目标 2k QPS；验收 2.5k 稳态 + 4k 冲刺；鉴权类接口 P99 ≤ 30ms |
| 会话模型 | 多会话：登录不递增 `token_version`；登出/改密/停用撤销该账号全部令牌 |
| 令牌作废时效 | 正常 ≤ 1 秒；Redis 故障 ≤ 30 秒；实例重启立即；数据库故障时受影响用户被拒 |
| 全局作废 | 密钥轮换：移除旧密钥，旧令牌验签失败返回 40100；不新增全局版本字段/接口 |
| 首次登录 | `sys_user.must_change_password`；初始 admin 由启动器按环境变量创建 |
| 角色继承语义 | `inherit_role_id` 表示"从哪个角色继承权限"，不存储组织上下级 |
| 缓存重载失败姿态 | fail-open，预留 `stale-policy` 开关 |
| 高可用投入 | MySQL / Redis / Nginx 全部单点，无自动故障切换 |
| 技术栈 | Java 21 + Spring Boot 3.x + MyBatis + MySQL 8 + Redis；Vue 3 + TypeScript；不使用 Spring Security 框架 |

## 2. 系统操作者

| 操作者 | 能力 | 权限码 |
|---|---|---|
| 超级管理员 | 全部操作；不可被删除或降权 | `*` |
| 权限管理员 | 管理用户、角色、权限、授权关系，只读审计 | `sys:user:*`、`sys:role:*`、`sys:perm:*`、`sys:audit:read` |
| 审计员 | 只读审计日志 | `sys:audit:read` |
| 业务用户 | 按被授予的角色使用业务功能 | 业务权限码 |
| 外部服务（服务账号） | 机器对机器调用；可判定自己或指定用户是否拥有权限码 | 授予的业务权限码 |

超级管理员通过内置角色 `SUPER_ADMIN` 绑定权限码 `*` 实现，判定仍是普通权限码判定，主链路不出现 `if (isSuperAdmin)` 分支。

## 3. 范围

### 3.1 本期实现

| 模块 | 内容 |
|---|---|
| 认证 | 账号密码登录、登出、续期、修改密码 |
| 用户 | 增删改查、启停、重置密码、分配角色 |
| 角色 | 增删改查、启停、授权限 |
| 权限 | 增删改查、权限树维护 |
| 鉴权 | 接口级、菜单级、按钮级鉴权；统一入口；默认拒绝 |
| 前端权限 | 动态菜单、按钮指令、路由守卫 |
| 审计 | CHANGE 与 SECURITY 两类；同事务或独立落库 |
| 失效机制 | 权限变更后各实例标记 PermissionSnapshot stale 并重载 |

本系统不含任何业务功能。业务模块是使用方，与权限系统平级存在，两者只有两个耦合点：`@RequiresPermission` 与 `AuditRecorder`。

### 3.2 本期不做

| 排除项 | 原因 |
|---|---|
| 数据权限（行级、字段级） | 标准 RBAC 表达不了；将来需在鉴权后追加一层数据范围过滤 |
| 多租户 | 已确认单组织；将来按租户独立部署 |
| SSO、OAuth2、第三方认证 | 本期账号密码；接入时只需扩展认证模块，鉴权模块不受影响 |
| 字段级加密与数据脱敏 | 不属于权限系统职责 |
| 工作流审批 | 属业务流程；可通过"待生效角色"扩展 |
| 图形或短信验证码 | 本期未要求；登录防暴力破解用锁定与限流 |
| 业务功能本身 | 业务模块按需独立新增 |
| 代最终用户操作（act-as） | 需要用户身份委托，属 SSO/OAuth2 范畴，与机器对机器接入不同 |
| 会话级登出（只登出当前设备） | 需要 `jti` 或会话表，与"减少存储"的取舍冲突 |

## 4. 功能需求

### 4.1 认证（FR-A）

| 编号 | 需求 | 约束 |
|---|---|---|
| FR-A1 | 账号密码登录 | 密码以 BCrypt 存储；明文与哈希不得出现在日志、响应、审计中；账号不存在也执行一次 dummy BCrypt |
| FR-A2 | 返回 JWT | 载荷含 `sub`、`ver`、`kid`、`iss`、`aud`、`iat`、`exp`；不含角色与权限明细 |
| FR-A3 | 令牌有效期与续期 | 访问令牌 2 小时；登录不递增 `token_version`，多会话共存；续期不递增，只重读最新版本与账号状态 |
| FR-A4 | 登出 | `token_version` 自增 + 广播，时效见 FR-A9；撤销范围是**账号全部令牌**，不是当前令牌 |
| FR-A5 | 修改自己的密码 | 改密后所有历史令牌作废，时效见 FR-A9；清除 `must_change_password` |
| FR-A6 | 连续登录失败锁定 | 连续失败 5 次锁定 15 分钟 |
| FR-A7 | 停用账号不可登录且既有会话失效 | 走令牌作废通道 |
| FR-A8 | 登录限流 | 按账号 5 次/分钟、按 IP 20 次/分钟；IP 取可信代理解析结果；Redis 故障时关闭基于 Redis 的账号/IP 限流并告警，数据库失败锁定仍生效 |
| FR-A9 | 令牌作废的保证等级 | 见 4.1.1 |
| FR-A10 | 全局令牌作废 | 密钥泄露场景：按密钥轮换执行，移除旧密钥后旧令牌返回 40100；不新增全局版本字段/接口 |
| FR-A11 | 首次登录强制改密 | `must_change_password = 1` 时，仅允许改密、登出、`/api/auth/me`；该标志随身份快照加载，改密后置 0 |
| FR-A12 | 外部服务接入 | 专用账号调用 `/api/auth/login` 取得 JWT；判断自己用 `/api/auth/me`（本地缓存 ≤ 30 秒）或 `/api/auth/permit`；判断指定用户用 `/api/auth/permission-check`（`userId` + 权限码列表）；一服务一账号，禁止共用，禁止代最终用户操作 |

#### 4.1.1 FR-A9 时效承诺

| 条件 | 生效时间 | 机制 |
|---|---|---|
| 登出 / 改密 / 停用 | 广播后 ≤ 1 秒；广播丢失 ≤ 30 秒 | 递增 token_version 后发布 TOKEN_REVOKED |
| 正常（Redis 可用） | ≤ 1 秒 | 广播触发快照失效，下一次请求重载 |
| Redis 不可用或广播丢失 | ≤ 30 秒 | 身份快照软 TTL 到期后重载 |
| 实例重启或新增实例 | 立即 | 缓存为空，首个请求直接读库 |
| 数据库不可用 | 受影响用户立即被拒；其他用户按 fail-open 处理 | 见 [02 §11.3](./02-总体设计说明书.md) |

不得承诺"任何故障下都立即失效"。文档写"立即失效"而实现是最坏 30 秒，会让安全审计建立在错误假设上。

高风险账号需要更严格时效时，做法是缩短其令牌有效期，不新增特例通道或引入 `jti` 黑名单。

### 4.2 用户管理（FR-U）

| 编号 | 需求 | 约束 |
|---|---|---|
| FR-U1 | 分页列表，支持账号前缀与状态筛选 | 高频读接口，受 A 档约束 |
| FR-U2 | 新增、编辑、删除 | 删除为逻辑删除（`status = 2`）；新增必须提供初始密码，创建后 `must_change_password = 1` |
| FR-U3 | 启用、停用 | 停用触发会话失效广播 |
| FR-U4 | 重置密码 | 重置后该用户所有令牌作废，并置 `must_change_password = 1` |
| FR-U5 | 分配、回收角色 | 变更后权限秒级生效 |
| FR-U6 | 不可删除或停用超级管理员 | 见 FR-G1、FR-G2 |

### 4.3 角色管理（FR-R）

| 编号 | 需求 | 约束 |
|---|---|---|
| FR-R1 | 分页列表与详情 | 角色表百级，可全量缓存 |
| FR-R2 | 新增、编辑、删除 | `code` 全局唯一且创建后不可修改 |
| FR-R3 | 启用、停用 | 停用后其权限不再生效 |
| FR-R4 | 删除前校验引用 | 有用户绑定时禁止删除并提示数量 |
| FR-R5 | 分配、回收权限 | 变更后持有该角色的用户权限秒级生效 |
| FR-R6 | 内置角色不可删除 | `SUPER_ADMIN` 等受保护 |

### 4.4 权限管理（FR-P）

| 编号 | 需求 | 约束 |
|---|---|---|
| FR-P1 | 权限树查询 | 树形组织 |
| FR-P2 | 增删改查 | 分 `MENU` / `BUTTON` / `API` / `SYSTEM` |
| FR-P3 | 权限码全局唯一 | 创建后不可修改 |
| FR-P4 | 删除前校验引用 | 被角色引用时禁止删除并提示 |
| FR-P5 | 控制显隐与排序 | 前端渲染依赖 `sort` 与 `status` |

前端权限只决定展示，不是安全边界。真正的拦截只在后端 API 权限。每个受保护接口必须声明权限码，由构建门禁校验。

### 4.5 审计（FR-L）

两类事件的事务语义不同：

| 类别 | 覆盖 | 事务要求 |
|---|---|---|
| CHANGE | RBAC 域全部写操作；业务域白名单内的关键操作 | 与业务同事务：业务失败则审计不落库；审计失败则业务回滚 |
| SECURITY | 登录成功与失败、登出、令牌作废、越权访问、限流触发、缓存降级 | 独立事件，不与业务同事务；记录失败不得回滚业务 |

#### 4.5.1 审计范围（FR-L1）

| 范围 | 内容 |
|---|---|
| 全量 | RBAC 域全部写操作 |
| 白名单 | 业务域中被判定为关键的操作 |
| 不覆盖 | 业务域普通写操作与所有读操作 |

#### 4.5.2 业务白名单判据

判据为两个客观问题：影响面（影响 1 条还是成百上千条）、可逆性（能否恢复、数据是否离开系统）。

| 类别 | 判据 | 要求 | 例子 |
|---|---|---|---|
| 不可逆 + 数据外带 | 数据离开系统边界 | 必须审计 | 导出、下载、打印、外部推送 |
| 不可逆 + 影响面大 | 批量且难恢复 | 必须审计 | 批量删除、数据清除、批量导入覆盖、审批、批量授权 |
| 可逆 + 影响面大 | 批量但能改回 | 应当审计 | 批量改状态 |
| 影响面小 | 单条增删改 | 可选 | 新增一条记录 |
| 纯读 | 不改变且不出系统 | 不审计 | 列表与详情查询 |

导出类易被漏判为"只是查询"，但数据离开系统本身必须留痕。

业务接口必须显式声明审计意图：调用 `AuditRecorder`，或标注 `@NoAudit("原因")`。两者皆无视为未完成，由构建门禁拦截。

#### 4.5.3 其他要求

| 编号 | 需求 |
|---|---|
| FR-L2 | 审计内容：类别、操作人、操作类型、目标对象类型与 ID、变更前后快照（脱敏）、事件时间、来源 IP、User-Agent、traceId |
| FR-L3 | CHANGE 与业务同事务，不允许异步或事后补偿 |
| FR-L4 | SECURITY 独立落库，写入失败不回滚业务 |
| FR-L5 | CHANGE 不允许丢弃；SECURITY 持续失败时允许丢弃但必须计数与告警 |
| FR-L6 | 审计日志只读，不提供修改与删除接口 |
| FR-L7 | 审计查询支持按类别、时间范围、操作人、操作类型、目标对象筛选；游标分页 |
| FR-L8 | 默认保留 180 天；归档与清理动作本身记录系统日志 |
| FR-L9 | 登录失败必须记录，含账号不存在的情况（`operator_id` 允许为空） |
| FR-L10 | 变更前后快照必须经过脱敏过滤器 |
| FR-L11 | 不存在"业务成功但 CHANGE 审计缺失"的情况 |
| FR-L12 | 业务接口必须显式声明审计意图 |
| FR-L13 | `target_type` 对业务域开放取值（如 `ORDER`） |
| FR-L14 | 业务快照的脱敏由业务模块自己负责（统一脱敏器只认识 RBAC 域字段） |
| FR-L15 | 导出类操作必须记录范围、结果条数与筛选条件 |

FR-L5 的取舍：SECURITY 事件量级远大于 CHANGE，若一律不可丢弃，会让纯记录动作反噬可用性。丢弃必须留下计数与告警。

FR-L14 的取舍：统一脱敏器无法预知业务字段的敏感规则。这意味着"业务模块忘记脱敏"是真实风险，兜底方式是审计接口只接受已脱敏数据，并列入接口自查清单。不为少数导出操作引入可注册的脱敏规则框架。

### 4.6 内置保护规则（FR-G）

这些规则不写在鉴权主链路上，而是作为数据规则与校验器存在：

| 编号 | 规则 |
|---|---|
| FR-G1 | `SUPER_ADMIN` 不可删除或停用；其权限集合不可移除 `*` |
| FR-G2 | 系统必须保留至少 1 个启用的超级管理员 |
| FR-G3 | 用户不能删除或停用自己 |
| FR-G4 | 用户不能移除自己最后一个管理类角色 |
| FR-G5 | 权限码、角色码、账号创建后不可修改 |

FR-G1~FR-G4 的实现载体是 `ConstraintValidator` 校验链（见 [05 §3.4](./05-RBAC0到RBAC3演进设计.md)）。RBAC0 阶段链上放 4 个校验器，RBAC2 阶段继续追加。

## 5. 非功能需求

### 5.1 性能（NFR-1）

| 项 | 指标 |
|---|---|
| 负载规模 | 10,000 并发在线用户 |
| 推导峰值 | 2,500 QPS |
| 设计目标 | 2,000 QPS（推导峰值留 25% 余量，不是限流阈值） |
| 验收场景 | 2,500 QPS 稳态 + 4,000 QPS 冲刺 |
| 鉴权类接口 | 服务器侧 P99 ≤ 30ms |
| 复杂管理类接口 | P99 ≤ 200ms |
| 缓存失效后首次请求 | P99 ≤ 100ms |
| 错误率 | < 0.1% |
| 缓存命中率 | > 99.9% |

文中毫秒与微秒数字是预算假设，不是实现保证；验收以压测实测为准，引用时必须标明是预算还是实测。

接口分两档的原因：低频接口（审计深翻页）压到 30ms 需要额外索引与存储成本，不经济。

### 5.2 可用性（NFR-2）

| 项 | 要求 |
|---|---|
| 部署形态 | 后端无状态，3 实例起步，支持滚动发布 |
| 高可用现状 | MySQL / Redis / Nginx 均为单实例，无自动故障切换；这是成本取舍 |
| Redis 故障 | 权限与令牌变更退化为 TTL 兜底（最坏 30 秒）；登录与鉴权不中断 |
| 数据库故障 | fail-open：鉴权继续用最后一份成功数据；已知状态变化的用户被拒；从未成功加载缓存的实例拒绝鉴权 |
| 应用实例故障 | 负载均衡摘除，用户无感知 |
| RTO | 应用 ≤ 5 分钟；Nginx ≤ 30 分钟（机器重建 ≤ 4 小时）；MySQL ≤ 1 小时（binlog 完好，否则 ≤ 24 小时）；Redis ≤ 5 分钟 |
| RPO | 权限数据 ≈ 0（需 binlog 开启且备份异机）；不满足则退化为自上次全备 |
| 可用性口径 | 鉴权读路径 99.9%；含写操作的端到端受 MySQL 单点约束，不承诺 99.9% |

### 5.3 安全（NFR-3）

| 项 | 要求 |
|---|---|
| 密码存储 | BCrypt 强度 10~12；禁止 MD5/SHA1/明文 |
| 密码策略 | 长度 ≥ 8，含大小写字母与数字；不得与账号相同 |
| 传输 | 全链路 HTTPS；令牌只放 `Authorization` 头，不放 URL 参数 |
| 令牌 | HS256；密钥 ≥ 256 位，由环境变量或配置中心下发；轮换三阶段协议；实例启动校验 kid 映射一致 |
| 会话作废 | 登出、改密、停用、密钥轮换均使历史令牌失效；登录不作为撤销手段；时效见 FR-A9 |
| 客户端 IP | 只信任可信代理的 `X-Forwarded-For`；由唯一组件解析；限流、审计、告警共用结果 |
| 防暴力破解 | 登录失败计数 + 锁定 + 双维度限流 |
| 防越权 | 垂直越权由权限码拦截；水平越权由业务模块自行做归属校验 |
| CSRF | 令牌放自定义请求头而非 Cookie；禁用 Cookie 会话 |
| CORS | 白名单精确配置，禁止 `*` 与凭据共存 |
| XSS | 前端转义动态内容；响应 `Content-Type: application/json` |
| SQL 注入 | 全部使用 `#{}` 参数绑定，禁止 `${}` |
| 敏感信息 | 密码、令牌、密钥不得出现在日志、异常堆栈、审计快照 |
| 权限最小化 | 新用户与新角色默认无任何权限 |
| 审计不可抵赖 | 记录操作人真实身份与来源 IP；审计日志不提供修改/删除接口，清理由独立运维任务执行 |

### 5.4 可观测性（NFR-4）

| 项 | 要求 |
|---|---|
| 指标暴露 | Actuator + Micrometer，Prometheus 格式 |
| 接口指标 | 每接口耗时分位图、QPS、错误率（按 401/403/5xx 分类） |
| 鉴权指标 | 鉴权耗时直方图（单独埋点）；403 次数（按权限码） |
| 缓存指标 | 命中率、`PermissionSnapshot` 重建次数与耗时、重建失败次数、快照版本一致性、当前陈旧时长、受影响用户数、用陈旧权限放行的请求数 |
| 日志 | 结构化 JSON；异步 Appender；丢弃条数须告警 |
| 链路追踪 | 每请求生成 traceId 并写入响应头 |
| 慢请求 | 超过阈值时记录用户、权限码、SQL |

缓存指标是硬要求：fail-open 姿态下，缺少陈旧时长与放行请求数就无法判断是否正在使用过期权限。

### 5.5 可维护性与可演进性（NFR-5）

| 项 | 要求 |
|---|---|
| 升级代价 | 升级到 RBAC1/2 时，业务接口的权限声明与鉴权入口契约不变；改动限于权限计算实现、快照加载 SQL、管理端与前端配置、迁移脚本与回归测试 |
| 可测试性 | 权限计算可脱离 HTTP 单独测试；覆盖全部路径 |
| 模块边界 | ArchUnit 在构建期强制，违反即失败 |
| 接口稳定性 | 接口路径与权限码一经发布视为契约 |
| 文档同步 | 数据模型或权限码变更时同步更新 03 / 04 |

不得使用"改动 0 行"这类表述。

### 5.6 环境约束（NFR-6）

| 项 | 约束 |
|---|---|
| 服务器资源 | 按够用加高可用冗余配置，不做过度采购 |
| 运行环境 | Linux；JDK 21；MySQL 8.0；Redis 6+；Nginx 前置 |
| 浏览器 | Chrome / Edge 最近两个大版本 |

### 5.7 一致性（NFR-7）

| 项 | 要求 |
|---|---|
| 事务边界 | 一次管理操作 = 一个事务（业务数据 + CHANGE 审计） |
| 缓存一致性 | `PermissionSnapshot` 整体重载并原子替换；身份快照按 userId 失效；避免多实例互相覆盖 |
| 失效时效 | 正常 ≤ 1 秒；Redis 故障 ≤ 30 秒 |
| 幂等性 | 授权与回收天然幂等；创建类以唯一约束兜底 |

### 5.8 质量门禁（NFR-8）

| 门禁 | 内容 |
|---|---|
| 接口权限覆盖 | 每个 `@RequestMapping` 方法必须有且只有一个方法级鉴权注解；Actuator/OPTIONS 走 allowlist |
| 权限码一致性 | 代码引用的权限码必须在初始化数据中有定义，且 `@RequiresPermission` 只使用 API 或通配码 |
| 审计声明 | 未来 `biz-*` 模块的敏感关键词接口必须调用 `AuditRecorder` 或标注 `@NoAudit`；RBAC 管理端由应用服务层审计 |
| 首次改密 | mustChangePassword 时仅允许改密/登出/me |
| 缓存快照 | 失效后整体重载、原子替换、失败保留旧值 |
| 模块依赖 | ArchUnit 校验 R-1/R-2/R-3/R-5/R-6/R-8；R-4/R-7 无业务模块时不适用，R-9 由契约单实现约束 |
| 权限计算单测 | 覆盖无角色、单角色、多角色、停用角色、停用权限、超级管理员 |
| 越权集成测试 | 低权账号访问高权接口返回 403 |
| SQL 索引 | 关键 SQL 的 `EXPLAIN` 断言（待目标环境执行） |
| 性能回归 | 按档位压测，A 档不达标则阻断发布（待目标环境执行） |

## 6. 关键用例

### UC-1 登录

```text
前置：账号已创建且启用
1. 提交账号与密码
2. 校验限流、账号状态、失败次数；账号不存在也执行一次 dummy BCrypt
3. 读取当前 token_version（不递增，多会话）
4. 生成 JWT（含 sub、ver、kid、iss、aud、iat、exp）
5. 记录登录安全事件
6. 返回令牌、用户基本信息与 mustChangePassword

异常：
2a 账号或密码错误 → 失败计数 +1，提示不区分两者（防账号枚举）
2b 账号停用 → 提示联系管理员
2c 连续失败超阈值 → 锁定并提示剩余时间
2d Redis 不可用 → 关闭基于 Redis 的账号/IP 限流并告警，数据库账号锁定仍生效
```

BCrypt 校验需 50~150ms，登录接口不受 30ms 约束；以限流和账号锁定为主要保护，不单独建线程池。

### UC-2 调整角色的权限

```text
1. 提交角色 ID 与新的权限码集合（含 expectedVersion）
2. 校验操作者权限（sys:role:assign-perm）
3. 事务内：锁角色行 → 校验约束 → 覆盖写入关系表 + 写 CHANGE 审计 → 提交
4. 提交成功后：自增版本号 + 发布 PERM_CHANGED，各实例标记 PermissionSnapshot stale
5. 返回成功

异常：
1a expectedVersion 不匹配 → 40950
3a 校验失败（如试图移除内置角色的 *）→ 回滚并返回明确错误
4a Redis 不可用 → 操作仍成功；告警；靠软 TTL 兜底
```

必须"先提交事务，后发广播"：反序会把旧数据写回缓存。

### UC-3 访问受保护接口

```text
1. 过滤器解析令牌、验签、检查 exp/iat/iss/aud
2. 取身份快照，校验 tokenVersion、enabled 与 mustChangePassword
3. 若 mustChangePassword=true，仅放行改密/登出/me
4. 读取方法上的 @RequiresPermission；无注解则拒绝
5. 从 PermissionSnapshot 计算权限码集合（stale/未命中则单飞整体重建）
6. 判定集合是否包含所需权限码
7. 通过 → 写入请求上下文并放行；不通过 → 403
```

缓存命中时无网络与数据库访问，P99 目标 < 1ms；未命中时只有首个请求触发快照重建。

### UC-4 权限变更的跨实例生效

```text
1. 实例 A 提交变更事务，成功后发布 PERM_CHANGED
2. 实例 B、C 收到通知后标记 PermissionSnapshot stale（不立即重载）
3. 各实例在下一个请求到来时整体重载，单飞保证同一时刻只有一个线程查库
4. 重启或重连的实例：启动时加载 PermissionSnapshot；订阅重连后标记全部快照 stale
预期时效：正常 ≤ 1 秒；Redis 不可用 ≤ 30 秒
```

采用惰性重载而非立即重载：立即重载会让 N 个实例同时查库，形成流量尖峰。

## 7. 验收标准

| 编号 | 验收项 | 判定方式 |
|---|---|---|
| AC-1 | RBAC0 全部功能需求可用 | 功能测试用例通过 |
| AC-2 | 鉴权类接口 P99 ≤ 30ms | 2,500 QPS 稳态压测 |
| AC-3 | 权限变更 1 秒内在全部实例生效（Redis 正常） | 多实例联调 |
| AC-4 | 停用 Redis 后鉴权不中断，变更与令牌作废 30 秒内生效 | 故障演练 |
| AC-5 | 每个受保护接口均有权限码声明 | 构建门禁 |
| AC-6 | 低权用户访问高权接口返回 403 | 越权测试集 |
| AC-7 | 无"业务成功但 CHANGE 审计缺失"的情况 | 事务异常注入 |
| AC-8 | 升级 RBAC1 的预演：权限声明与鉴权入口契约不变，回归通过 | 阶段 0 末期执行一次 |
| AC-9 | 滚动重启全部实例期间，已作废令牌一律被拒（40101） | 场景 S12 |
| AC-10 | 数据库故障期间按 fail-open 继续服务，且陈旧时长、受影响用户数、放行请求数可观测；恢复后立即重载并归零 | 场景 S14 |
| AC-11 | 并发覆盖式授权不产生静默丢失：恰好一个成功、一个返回 40950 | 场景 S15 |
| AC-12 | 密钥轮换期间无因 kid 不匹配导致的 401；移除旧密钥后旧令牌返回 40100；阶段 1、2 可回滚 | 场景 S13 |
| AC-13 | 备份恢复演练实测耗时符合 RTO 承诺，数据完整 | 场景 S18，每季度重复 |
| AC-14 | 用户列表与审计查询在目标数据量下索引达标 | 场景 S17 的执行计划报告 |
| AC-15 | 所有业务接口已显式声明审计意图，门禁零豁免通过 | 构建门禁（含删除一个声明验证它会失败） |
| AC-16 | 白名单内的导出与批量操作可查到操作人、条件与结果条数 | 功能测试 + 审计查询验证 |
| AC-17 | 多会话：同一账号第二次登录后第一个令牌仍可用；任一次登出后全部令牌返回 40101 | 多实例联调 |
| AC-18 | 初始 admin 首次登录后只能改密/登出/me，改密后恢复正常 | 功能测试 |
| AC-19 | 专用服务账号登录取得令牌后可调用 `/api/auth/me`；其权限变更 1 秒内影响判定 | 联调 + 变更注入 |
| AC-21 | `/api/auth/permission-check` 对指定用户的判定与内部鉴权一致：无角色、单角色、多角色、停用角色、停用权限、停用用户、不存在用户均符合预期 | 对照测试（同一用户、同一权限码，与 `PermissionResolver` 结果逐条比对） |
| AC-20 | 服务账号调 logout 后，该账号所有令牌（含其他进程）在时效内被拒 | 多进程联调 |

AC-8 需在 RBAC0 上线前执行一次升级预演，用于验证预留设计有效。

AC-9 ~ AC-21 覆盖"系统在最坏情况下是否仍正确拒绝、是否可观测"，其中 AC-10 是 fail-open 选择的直接后果，AC-17 固定多会话语义，AC-19/AC-20/AC-21 固定外部服务接入语义。

## 8. 约束与假设

| 编号 | 假设 | 不成立时的影响 |
|---|---|---|
| AS-1 | 用户 ≤ 1 万（远期 5 万）；角色 ≤ 200；权限点 ≤ 3000 | 超出需重新评估缓存内存与重载耗时 |
| AS-2 | RBAC 写操作 QPS < 1；业务白名单审计为人工触发，总写 QPS 仍 < 1 | 写量级上升 100 倍需改为异步或分库 |
| AS-3 | 每用户每分钟 6~10 次操作 | 若为每秒多次，QPS 上升一个数量级需扩容 |
| AS-4 | 应用、数据库、Redis 同机房（内网延迟 < 0.5ms） | 跨机房需重算 30ms 预算 |
| AS-5 | 鉴权只做是/否判定，不做数据范围过滤 | 见 3.2 |
| AS-6 | 正向授权，无拒绝优先规则 | 引入拒绝优先需在权限计算中加优先级 |
| AS-7 | 缓存重载失败姿态为 fail-open | 改为 fail-closed 需重写可用性目标与场景 S14 |
| AS-8 | MySQL / Redis / Nginx 单点，依赖人工恢复 | 要承诺端到端 99.9% 必须先为 MySQL 做高可用 |
| AS-9 | 备份与 binlog 存放在数据库主机之外 | 否则 RPO 从 ≈0 退化为最长 24 小时 |
| AS-10 | Redis 只承载可丢弃数据，不存业务数据 | 否则 Redis 从加速器变成必须高可用的存储 |
| AS-11 | 多会话：同一账号可持有多个有效令牌；登出为账号级，无法只登出单设备 | 需要单设备登出时，必须引入会话表或 `jti` |
